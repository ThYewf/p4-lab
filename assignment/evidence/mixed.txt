### A4. Observations

The old s2 switch successfully matched tunnel destination ID 2 and forwarded the packet to port 2.

The repeated experiment confirmed that h2's Ethernet interface received the packet.

The captured bytes include:

```text
08 00 | 00 02 | 07 | 45 00 ...
proto | dst   | hop| IPv4
```

Although the old switch expects a four-byte tunnel header and therefore begins IPv4 parsing one byte too early, the extra hop-limit byte remains present in the transmitted packet.

The captured frame retains the upgraded five-byte tunnel layout and the original application payload.

**Finding:** Mixed-version delivery succeeds at the Ethernet-frame level in this test, despite the old switch interpreting the encapsulated IPv4 header incorrectly. Application-level reception must be evaluated separately.

### A5. Application-Level Reception

Command:

```text
sh cat logs/h2.txt logs/h3.txt
```

Output:

```text
Listening on h2-eth0...
Listening on h3-eth0...
```

Neither receiver reported the `mixed` payload.

**Observation:** tcpdump confirmed that the Ethernet frame reached h2, including the new hop-limit byte and original payload. However, `receive.py` did not report successful application-level reception.

The old switch interpreted the IPv4 header using the original four-byte tunnel layout, while the transmitted frame contained the new five-byte layout. The experiment demonstrates partial wire-format compatibility, but does not establish the exact cause of the missing application-level output.

**Conclusion:** Mixed-version forwarding succeeded at the Ethernet level but did not achieve observable application-level delivery. The old switch's ability to forward the packet should not be treated as proof of full protocol compatibility.

## B. Mixed-Version Loop Test

## C. Summary of Observations

1. The old s2 switch recognised the unchanged tunnel destination ID and selected the expected forwarding port, but successful application delivery was not observed.
2. The old switch parsed the encapsulated IPv4 header using the original four-byte tunnel-header layout, which is incompatible with the new five-byte format.
3. In the mixed-version loop, s2 continued forwarding packets without enforcing a hop limit.
4. The upgraded s1 switch eventually detected `hop_limit == 0` and dropped the packet. Both switch processing counts then remained stable.

**Conclusion:** Mixed-version deployment does not guarantee end-to-end packet-format compatibility. However, this experiment demonstrates that an upgraded switch on the loop path can enforce a finite hop limit even when another switch is still running the original program.
